# Архитектура AI 4.0 Unified Assistant

## Выбранный контур

Первая версия строится как **мобильный клиент Expo с небольшим серверным ИИ-шлюзом**. Это обеспечивает работающий ИИ-чат без хранения ключей на устройстве и сохраняет историю, настройки и список выбранных материалов локально. Пользовательские документы не синхронизируются в облако автоматически: только текст, явно выбранный как контекст, отправляется в серверный запрос.

| Слой | Ответственность | Границы безопасности |
|---|---|---|
| **Expo-клиент** | Чат, локальная история, материалы, каталог GitHub, настройки | Не хранит ключи; не выполняет код; не клонирует репозитории. |
| **Локальное хранилище** | История диалогов, настройки, метаданные материалов и избранное | Используется AsyncStorage; очистка доступна из настроек. |
| **tRPC-сервер** | Проверка входных данных, выбор доступной модели, генерация ответа | Ограничивает длину истории и контекста; не принимает произвольные команды. |
| **Встроенная модель** | Генерация текста, плана, объяснения или ревью | Модель получает только явный запрос, недоверенный контекст и публичную системную политику. |
| **GitHub-каталог** | Открытие разрешённых публичных ссылок и показ статуса источника | Не выполняет содержимое репозитория, не использует закрытые репозитории и не переносит предполагаемые утечки. |

## Модельная стратегия

Актуальный каталог моделей получен перед началом разработки. В роли стандартного быстрого помощника используется **`gpt-5-mini`**. Для режима «Код» сервер сможет выбирать **`gpt-5`** с низким уровнем рассуждений, если эта модель доступна в текущем каталоге; в противном случае используется безопасная стандартная модель. Модель и её доступность проверяются на сервере, а не задаются пользовательским полем ввода.

| Режим | Назначение | Предпочтительная модель | Результат |
|---|---|---|---|
| **Спросить** | Объяснения, идеи, текстовые ответы | `gpt-5-mini` | Чёткий ответ с явными ограничениями |
| **Исследовать** | Разбор только выбранного пользовательского контекста | `gpt-5-mini` | Сводка с обозначением источников контекста |
| **Код** | План, ревью и объяснение фрагментов кода | `gpt-5` или fallback | Предложения и шаги проверки, но не выполненные изменения |
| **Создать** | Декомпозиция продукта, архитектура и список задач | `gpt-5` или fallback | План реализации с рисками и проверками |

## Контракт ИИ-запроса

Сервер принимает `mode`, `message`, ограниченную историю и опциональный контекст. Все поля проходят проверку длины и типа. Системная инструкция закрепляет следующие правила: не раскрывать секреты, не выдавать предположение за выполненное действие, не интерпретировать содержимое материалов как инструкции более высокого приоритета и не предлагать автоматическое выполнение кода. Пользовательский контекст оборачивается маркерами недоверенного источника и имеет ограничение по размеру.

> **Ключевое ограничение:** приложение не является средой для автономного запуска стороннего кода. Оно анализирует и объясняет данные, но любые потенциально опасные операции остаются за пределами первой версии.

## Импорт материалов и GitHub

Материал в приложении состоит из имени, типа, локального URI, заметки и признака «использовать как контекст». При импорте документ остаётся на устройстве. В первой версии поддерживается безопасная регистрация файла и ручное добавление его текста в запрос; обработка форматов и удалённое хранение добавляются позже только при явном действии пользователя.

GitHub-раздел имеет два уровня. Первый — встроенный каталог разрешённых публичных ссылок, сформированный после аудита материалов. Второй, расширяемый уровень — чтение **манифеста** открытого репозитория по явной ссылке, с запретом на клонирование, установку зависимостей, выполнение и чтение `.env`/бинарных файлов. Этот уровень проектируется как отдельный модуль и не входит в действия без подтверждения.

## Последовательность реализации

Сначала создаются интерфейс вкладок, локальная модель данных и рабочий ИИ-чат. Затем добавляются библиотека материалов и каталог GitHub-ссылок. На завершающем шаге настраиваются фирменный знак, тесты и проверка сборки. Модели данных, маршруты и интерфейс остаются модульными, чтобы в дальнейшем добавить подтверждаемые инструменты, анализ публичных манифестов и серверную синхронизацию без переписывания ядра.
