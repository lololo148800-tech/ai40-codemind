# Собственный AI40 Gateway

AI40 Gateway предоставляет OpenAI-compatible text chat endpoint внутри вашего проекта. Внешний Python-агент и другие доверенные клиенты используют **ваш** `AI40_API_KEY`; ключ OpenRouter в этом режиме не нужен. Внутренние credentials среды остаются на сервере и не передаются клиенту.

## Выпуск ключа

В приложении откройте **Настройки → Ключи доступа → Войти в проект**. После входа создайте ключ с понятным именем и сохраните его в менеджер секретов: экран показывает секрет только один раз. Ключ имеет scope `agent:run`, не даёт shell-доступ, изменения файлов или APK-сборку.

## Подключение Python-агента

Используйте версию `agent.py`, обновлённую вместе с этим проектом:

```bash
export AI40_API_KEY="ai40_live_…"
export AI40_API_BASE_URL="https://<api-домен-проекта>/api/v1"
export AI40_MODEL="ai40-code"
python3 agent.py --agent "Проведи независимое code review и предложи тесты"
```

`AI40_MODEL` принимает `ai40-code`, `ai40-fast`, `ai40-reason` или ID доступной runtime-модели. Gateway выбирает доступную модель по текущему серверному каталогу, поэтому не привязан к устаревшему статическому model ID. Для длинного результата `tools/agent.py --stream "задача"` включает совместимый SSE-режим.

## Совместимый контракт

| Endpoint | Авторизация | Назначение |
|---|---|---|
| `GET /api/v1/models` | `models:read` | Псевдонимы AI40 и текущие доступные модели |
| `POST /api/v1/chat/completions` | `chat:complete` | Text-only completion, включая совместимый SSE при `stream: true` |
| `POST /api/v1/worker/plan` | `worker:plan` | Approval-first runbook; не запускает команды, тесты или APK-сборку |

Gateway принимает до 25 text-сообщений и максимум 4 000 output tokens. Он не принимает произвольные инструменты, не открывает shell и не заменяет изолированный worker; это защищённый AI ingress, а не доступ к инфраструктуре проекта.

## Безопасность

Самодельный AI40 ключ работает только с вашим AI40 gateway. Он не является и не может быть замещающим ключом для OpenRouter, Anthropic, OpenAI или других внешних сервисов. Минимальное техническое ограничение интенсивности на ключ остаётся включённым для защиты backend от случайного fan-out и злоупотребления; это не пользовательская подписка и не способ выставлять лимиты на ключи.
